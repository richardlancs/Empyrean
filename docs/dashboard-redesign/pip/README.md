# Pip, the camera companion

Branch `feature/pip-companion`, from `85e099d` (`feature/demo-model-toggle`). Same
layout, same engine; Pip moves onto the camera frame and becomes a help button.

## What Pip does

- **Where:** in the camera panel's state row, feet on the picture's top edge. The
  row reserves Pip's height, so Pip never covers the picture, the detection labels,
  the camera status or any control (checked at 360, 768, 1440 px and 200 % zoom).
  Wide screens show Pip reclining (64 px tall); narrow screens a smaller peek (36 px).
- **Help button:** a real `<button>` named "Help with the camera." with the artwork
  as a decorative image (`alt=""`). Enter, Space, click or tap opens a help bubble
  under Pip (a disclosure: `aria-expanded`, no focus trap). Escape or **Close help**
  closes it and returns focus to Pip; a press elsewhere closes it without moving
  focus. If the artwork fails to load, the button shows the word "Help".
- **Bubble text** (real HTML, from confirmed state only):
  - Regular: "I’m using the general-purpose detector."
  - Demo, trained checkpoint: "I’m using the model trained for our demo objects."
  - Demo, YOLOE fallback: "I’m using a fallback detector, not the model trained for our demo objects."
  - Fake vision: "This is a recorded test clip, so no detector is running. The control is set to …"
  - plus "Keep the object and your hand in view.", a recovery line when something is
    wrong, and "To change the detector, use the Regular | Demo control above."
    Pip has no switch of its own.
- **Poses** (`selectPip` in `features/experience/selectors.js`):

| Pose | File | When |
|---|---|---|
| Reclining | `pip-recline.png` (narrow: `pip-peek-edge.png`) | camera live, nothing needs attention |
| Attentive, pointing | `pip-point.png` (existing) | something is being touched |
| Waiting | `pip-wait.png` | vision reports a detector switch in progress (not merely a click) |
| Concerned | `pip-concerned.png` | camera offline, stream dropped, picture stale, frame times unknown, or the last switch failed; each with a specific recovery line |
| Sign-holding | `pip-peek.png` (existing) | "How touch works" in the touch card (onboarding) |

- **Hazards:** during an active real warning, `layout.css` hides every Pip, the
  camera companion and its bubble (the same hook as before).
- **Never claimed:** listening, microphone input, recognition success or sound.
  A unit test checks Pip's sentences for those words.

## Motion (designed with Codex)

Claude Code wrote the first version; Codex (`codex exec`, read-only) reviewed it
against the screenshots and constraints and ranked seven changes. Adopted:

1. Entrances never move the feet below the frame edge (bottom-anchored scale, not a slide).
2. One entrance per **confirmed pose change**, never on first load or a breakpoint
   image swap: reclining 260 ms `scaleY(.97→1)`, attentive 180 ms `scale(.96→1)`,
   waiting 220 ms `scaleY(.98→1)`, concerned appears at once. Easing
   `cubic-bezier(.2,.7,.3,1)`, no overshoot, no loops.
3. Interaction motion is separate from pose motion: a −3° head tilt and 2 px lift on
   keyboard focus, and on hover only for fine pointers.
4. Waiting and concerned stay still; the words carry the state.
5. The bubble fades from 0.85 opacity over 120 ms; its height and position change at once.
6. Reduced motion: no animation, transition or transform at all.
7. The entrance class is removed on a timer, so an entrance hidden by a hazard never
   replays when the warning clears.

Changed from Codex's advice: it suggested dropping the tilt; the brief asks for a head
tilt or raised paw, so a smaller tilt (−3° instead of −6°) was kept.
